AWS services that do the work

Ten managed services. Nothing to patch, and nothing runs unless something calls for it: the half-hourly read, a new exposure window, a clock's deadline or a visitor.

EventBridge Scheduler

Starts the reading workflow every 30 minutes, so nobody has to press anything.

rate(30 minutes), with a 5-minute flexible window.

Step Functions

Two workflows. The reading workflow reads every source in parallel, then publishes the board. The clock workflow runs once per person, over the list of deadlines in the code.

Standard workflows. A Distributed Map runs each source as a short Express child, 6 at a time, retries a failed page with jittered backoff, and carries on if up to half fail. The clock is a Map over the deadlines: each is a Wait state on an exact time, and each "did you act?" is a task token whose timeout is the deadline. Every clock step retries.

Lambda

Five functions: read one source, publish the board snapshot, answer the website's API, match new windows to saved trips, and run each clock step.

Python 3.12 on arm64 (Graviton), 512 MB to 1.7 GB (the matcher gets one full vCPU, for an airport exposure with hundreds of matches), one shared layer. Billed by the millisecond.

Bedrock

Runs Claude Haiku 4.5 for two jobs: reading notices, and turning your trip into places and times.

The US cross-region inference profile, so your words stay in US Regions. Temperature 0, and every call is a forced tool call, so the answer always comes back as structured data that code can check.

DynamoDB

One table holds exposure windows, sources, saved trips, clocks, Lab results and request counters.

On-demand billing, one secondary index, encrypted at rest. Time to live deletes saved trips, clocks, Lab results and counters on schedule.

DynamoDB Streams

Sends each new exposure window to the matcher the moment it is stored, so a saved trip hears about it without anyone checking.

A filter passes only INSERTs of window items. Reading a notice again rewrites the same item, so it never re-sends. Saved stops are indexed by state and day, so the matcher reads only the trips that could match. Batches retry three times, split in half on error, and anything left goes to SQS. In a drill, a new window reached a saved trip in 5.3 seconds.

S3

Two buckets. One holds this website and the board backup. The other keeps every notice read, filed by a hash of its text, and the list of sources.

Public access blocked on both; the site is reached only through CloudFront. The notice archive is encrypted.

API Gateway

An HTTP API with 15 routes: the board, one exposure, a check, saving, reading and deleting a trip, its calendar feed, alerts for a trip or a clock, the push key, starting and reading a clock, "I got it", the Lab and status.

Every route is throttled to 20 requests a second, bursts of 50. Checks, saved trips, alerts, clocks and the Lab also have a daily limit per visitor, counted under a scrambled form of the visitor's own address. Calls that skip CloudFront are refused.

CloudFront

Serves the site over HTTPS and sends API calls to API Gateway.

Origin access control to the private bucket. A CloudFront Function maps folder addresses to pages. An origin group serves the S3 board snapshot if the API returns 500, 502, 503 or 504; in a drill with the API returning 503, it served the same 20 rows. The board and status are cached for a minute; everything personal is never cached. HTTP/2 and HTTP/3, compressed.

SQS

Records any stream batch the matcher could not finish, even after retries, so a failure is never silent.

The stream's on-failure destination: it keeps where the batch was in the stream, for 14 days, encrypted. An alarm fires if one arrives, and scripts/replay.py runs the matcher again over the windows from that time.

AWS services that support it

Describing, watching, tracing and locking down the ten above.

SAM and CloudFormation

One template, template.yaml, describes every resource on this page.

Deployed as a CloudFormation change set, created and applied by the deploy script. No SAM CLI needed.

X-Ray

Traces a sample of every function's runs (the first each second and 5% of the rest) and both workflows, with a part for each DynamoDB, S3 and SSM call, each Claude call, each page fetched and each push sent, so a slow source or a slow model call shows up in one view. Its service map, kept to this stack, is drawn on the Ops page.

Active tracing on all five functions and both state machines, plus the X-Ray SDK in the layer. Outside calls are named by host only. A trace of the matcher found its own bottleneck in a scale test: 300 writes waiting on a third of a CPU.

CloudWatch and SNS

Logs every function run and turns log lines into metrics: pages read and failed, new windows and dropped proposals, Claude's cost and latency, check time, matching work per window, stored-to-matched time, pushes, and how late each clock window closed. Eight alarms: pages failing three runs in a row, a run failing, reads stopping (silence counts as failure), a clock failing, a batch the matcher could not finish, new windows waiting over a minute, the API answering with errors, and Claude spending over $1 an hour. One dashboard and five saved Logs Insights queries.

Metrics are Embedded Metric Format log lines, with no extra API calls. Everything is shown on the Ops page, read from CloudWatch at most every 10 minutes; the alarms are also on the status panel, and SNS can email whoever runs the stack. Logs are kept 14 days.

IAM

One role per function, granting only the table operations, buckets and workflows it uses. Only the API can start or resume a clock; only the reader and the API can call Bedrock, and only the one Claude Haiku 4.5 model; the board snapshot can write only its two files.

One role per function and per workflow, written in the template.

SSM Parameter Store

Holds the key that signs this site's push notifications, so only this site can send to your device.

A SecureString, made once by the deploy script. Never in the code or the template.

SES Off

Email reminders from your clock.

Built in, and switched off until a sender address is verified. The clock page and the calendar file work without it.

The AI

One small model that reads. Code decides everything that matters.

Claude Haiku 4.5

Reads each changed notice and lists every place and time in it, each with the exact sentence it came from. Turns your trip description into places and times.

us.anthropic.claude-haiku-4-5-20251001-v1:0, a small, fast model. A notice costs a median of $0.006 to read; the 27-page benchmark costs $0.19.

Anthropic Python SDK

Calls Claude on Bedrock with two tools, record_exposures and record_stops, and forces the model to answer through one of them.

Version 1.17.0 through its Bedrock client, in a Lambda layer with tzdata.

Checks in plain code

Every proposed window must quote the notice word for word, its date must be written in or just above the quote, its place must be named within a few lines, its times must be inside the quote, and its time zone must fit its state, or it is dropped or widened. Whether you overlapped, merging, and every deadline are computed by code from the CDC's rules.

On the 11 notices it was developed against it matched 34 of 34 hand-labeled windows exactly, start and end times included. On 3 held-out notices from departments it does not read, 3 of 5, with 0 false; the other 2 were read as one two-day window that still covers both days. On 13 pages that are not notices, it created 0. Wrong dates, places and quotes are rejected 114 of 114 times.

The code on Lambda

Python and its standard library. No web framework.

Python 3.12

Small modules: ingest fetches and finds new notices, reader asks Claude and evidence checks the answer against the text, match and trips compare a trip with each window, watch keeps saved trips and runs the matcher, push encrypts and signs notifications, merge joins reports of the same exposure, board builds the public board, rules runs the deadlines from a domain file (domains/measles.py, or domains/hepatitis_a.py), clock runs each clock step, api answers the site, store talks to DynamoDB, obs writes metrics and traces, ops reads them back for the Ops page, textutil cleans pages.

Standard library for the rest: urllib fetches pages, html.parser reads HTML and RSS, hashlib makes content hashes and ids, zoneinfo handles timezones, ipaddress keeps the Lab away from private addresses, statistics computes the median delay.

boto3

Talks to DynamoDB, S3 and Step Functions from inside the functions.

The copy that ships with the Lambda runtime, so the layer stays small. The AWS X-Ray SDK for Python, in the layer, traces its calls.

This website

Plain HTML, CSS and JavaScript, served from S3 through CloudFront.

HTML, CSS, JavaScript

Eight pages and a few small JavaScript modules. No framework and no bundler.

A short Python script, scripts/render.py, standard library only, adds the shared header and footer to each page.

The departures board

The split-flap letters on the board and in your result.

Drawn in JavaScript, and turned off when your device asks for reduced motion.

Calendar files and feeds

Every deadline as an event in your own calendar, with an alarm 12 hours before. A saved trip also has a feed your calendar subscribes to, so a new match appears on its own, at the calendar's next refresh.

Alerts on this device

A notification on your phone or computer when a new notice matches your trip, or a deadline is a day away.

Web Push: a small service worker, messages encrypted to your browser's key (RFC 8291) and signed by this site (RFC 8292), checked against the RFC's own test vector. No account, no app, no email.

Files are made in your browser. The feed is built by the API from your trip, and is reachable only by its unguessable address.

Light and dark

Follows your device's setting, with a switch in the header.

CSS custom properties. Your browser keeps only that choice, and your last result while the tab is open.

Bebas Neue and EB Garamond

The board's letters, and the calm voice of a public notice.

From Google Fonts. Pictures are open-licence photographs and posters, credited in the footer.

Building, deploying and checking

All run from a laptop or AWS CloudShell.

deploy.py

The one command: python scripts/deploy.py. Builds, uploads, deploys the stack, uploads the source list and the site, and clears the CloudFront cache.

boto3 only. build.py packs the layer from arm64 wheels, with no Docker.

pytest

41 tests: the CDC deadlines, the evidence checks, the clock plan, merging, trip matching, the stream matcher, Web Push against the RFC test vector, the API's own rules, and a second disease (hepatitis A) on the same code.

python -m pytest tests

The reader benchmark

Runs the reader on real notices labeled by hand (two of them held out), on measles pages that are not notices, and on answers broken on purpose. A second script runs it on real hepatitis A notices.

python bench/run.py, python bench/reuse.py

stats.py and cost.py

Count scheduled runs and their results, print the headline numbers from the live stack, and price a month from the stack's own metrics: about $3.60 at list price, about $1.65 inside the AWS Free Tier.

python scripts/stats.py, python scripts/cost.py

recheck.py and drill.py

Re-check every stored window against its archived notice without calling the model, and prove on the live stack the failover, the whole trip path (a drill notice read by Claude, matched through the stream, pushed) and a real-speed clock closing its window at the deadline.

python scripts/recheck.py, python scripts/drill.py failover, trip, clock

scale.py

Load-tests the live stack: 10,000 saved trips and new windows through the real stream, an airport exposure that 300 trips passed through, 200 windows at once, 2,000 requests through CloudFront, and 50 real-speed clocks at once. Then it deletes what it made.

python scripts/scale.py all; results in docs/scale.json and on the Ops page.
