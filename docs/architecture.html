Every 30 minutes

  1. 1Scheduler starts the ingest workflow.
  2. 2It reads the source list from S3.
  3. 3One Lambda run per page, 6 at a time.
  4. 4Only a changed page reaches Claude.
  5. 5The page is archived by its hash.
  6. 6Checked windows go to DynamoDB.
  7. 7A snapshot Lambda writes the board to S3.

When you check, and after

  1. 8CloudFront serves the site from S3.
  2. 9Live requests go through API Gateway.
  3. 10The API reads windows, saves your trip.
  4. 11Claude reads your trip. Nothing else.
  5. 12A new window enters the stream.
  6. 13The matcher writes any match into your trip.
  7. 14The matcher sends Web Push to your device.

Your clock

  1. 15The API starts your own workflow.
  2. 16Each deadline: Wait, then remind.
  3. 17"I got it" goes through the API, which sends the task token back.
  4. No answer by the deadline: the token times out, and the window closes on its own.
  5. The clock record deletes itself (TTL) the day after the watch ends.

Measured: 34 of 34 labelled windows exact, 3 of 5 held out (0 false); 0 windows from 13 non-notice pages. With 10,000 saved trips, an ordinary new window reads 150 to 190 times less than reading every trip, same matches.
